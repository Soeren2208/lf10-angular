# AB 02 – Mit Ticketlisten arbeiten

*Dauer: etwa eine Doppelstunde.*

## Die Situation

> Das Support-Ticket der HiTec GmbH hat jetzt eine feste Form. Die Support-Leitung will daraus **Auswertungen** sehen: Wie viele Tickets sind offen? Welche sind am dringendsten? Wie weit ist Ticket 4?
>
> Bisher hat sie das in der Excel-Tabelle von Hand gemacht: nach „offen“ **filtern**, nach Priorität **sortieren**, mit Strg + F ein Ticket **suchen**, die Zeilen **zählen**. Das soll die Weboberfläche künftig selbst können. Und wenn Jonas Beck ein Ticket erledigt, soll sich die Liste sofort ändern, ohne dass jemand die Tabelle neu öffnet.
>
> Dein Auftrag: Schreibe die Funktionen, die Ticketlisten auswerten und ändern.

## Lernziele

Nach Bearbeitung dieses Arbeitsblatts kannst du:

- **Pfeilfunktionen** lesen und schreiben
- mit `filter`, `map`, `find` und `reduce` Listen auswerten und für jede Frage die passende Methode wählen
- mit einem Ergebnis `undefined` umgehen, wenn `find` nichts findet
- erklären, warum `sort` eine Liste verändert, und eine **Kopie** davon sortieren
- ein Objekt in einer Liste **ändern, ohne die Liste zu verändern**

### Aufgabe 2 – Offene Tickets: erst mit Schleife, dann mit `filter`

*Etwa 15 Minuten.*

**B1** `openTickets` liefert alle Tickets mit dem Status `offen`.

```ts title="src/ticket-list.ts"
export function openTickets(tickets: readonly Ticket[]): Ticket[] {
  const result: Ticket[] = [];
  for (const ticket of tickets) {
    // Wenn das Ticket offen ist, hänge es mit result.push(ticket) an.
  }
  return result;
}
```

<Task id="ts-ab02-a2-test1">Starte `npm run test:ab02`. Die beiden Tests `B1 openTickets` müssen grün werden.</Task>

Jetzt kommt der Umbau. Dasselbe lässt sich kürzer sagen:

```ts
export function openTickets(tickets: readonly Ticket[]): Ticket[] {
  return tickets.filter((ticket) => ticket.status === 'offen');
}
```

Zwei Dinge sind neu: die Methode `filter` und die Schreibweise `(ticket) => …`.

**Was `filter` tut.** `filter` ist eine Methode jeder Liste. Sie bekommt eine **Funktion** übergeben und ruft diese Funktion **für jedes Element der Liste einmal** auf. Liefert die Funktion `true`, kommt das Element in die Ergebnisliste. Liefert sie `false`, bleibt es draußen. Am Ende gibt `filter` die neue Ergebnisliste zurück. Die ursprüngliche Liste bleibt unverändert.

**Was die Funktion in der Klammer ist.** `(ticket) => ticket.status === 'offen'` ist eine **Pfeilfunktion**, also eine Funktion ohne Namen, die man direkt dort hinschreibt, wo man sie braucht. In Java heißt das Lambda: `ticket -> ticket.getStatus().equals("offen")`.

| Teil | Bedeutung |
|---|---|
| `(ticket)` | Der **Parameter**: Hier trägt `filter` jeweils ein Element der Liste ein. |
| `=>` | Der Pfeil: „liefert“. |
| `ticket.status === 'offen'` | Der **Rückgabewert**. Der Vergleich ist `true` oder `false`. |

**Der Name des Parameters ist frei.** `(ticket) => …` und `(t) => …` tun dasselbe, nur muss rechts vom Pfeil derselbe Name stehen wie links. Üblich ist die Einzahl des Listennamens: Die Liste heißt `tickets`, ein Element heißt `ticket`. Das liest sich wie dein `for (const ticket of tickets)` von eben, und die Bedingung aus deinem `if` steht jetzt rechts vom Pfeil. Die Ergebnisliste, `push` und die Schleife übernimmt `filter`.

**Was beim Aufruf passiert.** Du rufst `openTickets` mit den ersten vier Beispieltickets auf:

| Durchlauf | `ticket` | `ticket.status === 'offen'` | Ergebnis |
|---|---|---|---|
| 1 | #1 (erledigt) | `false` | bleibt draußen |
| 2 | #2 (in Arbeit) | `false` | bleibt draußen |
| 3 | #3 (offen) | `true` | kommt in die Ergebnisliste |
| 4 | #4 (offen) | `true` | kommt in die Ergebnisliste |

Ergebnis: eine Liste mit #3 und #4.

### Aufgabe 4 – Tickets zählen mit `reduce`

*Etwa 25 Minuten. Das ist die anspruchsvollste Aufgabe des Arbeitsblatts.*

**B4** `countByStatus` liefert, wie viele Tickets es je Status gibt. Auch ein Status ohne Tickets kommt vor, mit 0:

```ts
{ offen: 4, 'in Arbeit': 2, erledigt: 2 }
```

Dafür brauchst du `reduce`: Aus der ganzen Liste wird **ein** Ergebnis, hier ein Objekt. Bevor du loslegst, ein einfacheres Beispiel. Es zählt alle Prioritäten zusammen:

```ts
tickets.reduce((sum, ticket) => sum + ticket.priority, 0);
```

`reduce` bekommt zwei Dinge: eine Funktion und einen **Startwert** (hier `0`). Die Funktion bekommt den bisherigen **Zwischenstand** (`sum`) und das nächste Element (`ticket`) und liefert den **neuen Zwischenstand**. So läuft es für die Prioritäten 3, 1 und 2:

| Schritt | Zwischenstand vorher | Priorität | neuer Zwischenstand |
|---|---|---|---|
| Start | | | `0` (Startwert) |
| 1 | `0` | `3` | `3` |
| 2 | `3` | `1` | `4` |
| 3 | `4` | `2` | `6` |

<Task id="ts-ab02-a4-trace">Welche Zwischenstände entstehen, wenn du dasselbe mit den Prioritäten 2, 2, 1 und 3 durchrechnest? Schreibe sie auf.</Task>

<details>
<summary>Auflösung</summary>

Start `0`, dann `2`, `4`, `5` und zum Schluss `8`. Das Ergebnis ist `8`.

</details>

Bei `countByStatus` ist der Zwischenstand kein Zahlenwert, sondern ein **Objekt**, das mitzählt. Um aus dem alten Zwischenstand einen neuen zu bauen, brauchst du zwei Schreibweisen, die du noch nicht kennst. Beide zeigt dir ein Beispiel mit einem anderen Objekt:

```ts
const a = { x: 1, y: 2 };

const b = { ...a, y: 5 };       // { x: 1, y: 5 }: alle Felder von a kopieren, y überschreiben
const key = 'z';
const c = { ...a, [key]: 9 };   // { x: 1, y: 2, z: 9 }: der Name des Feldes kommt aus dem Wert von key
```

- `{ ...a, y: 5 }` baut ein **neues** Objekt. `...a` kopiert alle Felder von `a`, ein Feld dahinter überschreibt das gleichnamige. Das ändert `a` nicht. Das nennt man den **Spread-Operator**.
- `[key]: 9` in eckigen Klammern heißt: Der **Name** des Feldes steht nicht fest, er ist der Wert von `key`.

Der Zwischenstand beginnt so:

```ts
{ offen: 0, 'in Arbeit': 0, erledigt: 0 }
```

und für jedes Ticket wird der Zähler seines Status um 1 erhöht.

<Task id="ts-ab02-a4-write">Schreibe `countByStatus` mit `reduce`. Gehe in Schritten vor, die Tipps helfen dir.</Task>

<details>
<summary>Tipp 1: Das Gerüst</summary>

```ts
export function countByStatus(tickets: readonly Ticket[]): Record<Status, number> {
  return tickets.reduce<Record<Status, number>>(
    (count, ticket) => /* hier kommt der neue Zwischenstand hin */,
    { offen: 0, 'in Arbeit': 0, erledigt: 0 },
  );
}
```

`Record<Status, number>` ist der Typ eines Objekts, das für **jeden** Status eine Zahl enthält. Mit `reduce<…>` sagst du dem Compiler, welchen Typ der Zwischenstand hat.

</details>

<details>
<summary>Tipp 2: Der neue Zwischenstand</summary>

Du brauchst ein **neues** Objekt, das so aussieht wie `count`, nur dass der Zähler für `ticket.status` um 1 größer ist. Das geht mit den beiden Schreibweisen von oben: `{ ...count, … }` kopiert alle Zähler, und das Feld dahinter überschreibt einen davon. Der Name dieses Feldes kommt aus einem Wert, steht also in eckigen Klammern: `[ticket.status]: …`.

</details>

<details>
<summary>Tipp 3: Die Zeile</summary>

```ts
(count, ticket) => ({ ...count, [ticket.status]: count[ticket.status] + 1 })
```

Die runden Klammern um das Objekt sind nötig, damit TypeScript die geschweiften Klammern als Objekt versteht und nicht als Block.

</details>

### Aufgabe 5 – Sortieren und das Versprechen der Funktion

*Etwa 15 Minuten.*

**B5** `sortedByPriority` liefert die Tickets mit der höchsten Dringlichkeit zuerst: erst Priorität 1, dann 2, dann 3. Bei gleicher Priorität kommt das Ticket mit der kleineren Nummer zuerst. Die Eingabeliste darf sich **nicht** ändern.

Die Vergleichsfunktion für `sort` steht schon da. Sie liefert eine Zahl: kleiner als 0, wenn `a` vor `b` kommt:

```ts
(a, b) => a.priority - b.priority || a.id - b.id
```

(Der zweite Teil nach `||` greift, wenn der erste 0 ist, also bei gleicher Priorität.)

<Task id="ts-ab02-a5-predict">Vorhersage: Du schreibst die Funktion so. Was meldet der Compiler?</Task>

```ts
export function sortedByPriority(tickets: readonly Ticket[]): Ticket[] {
  return tickets.sort((a, b) => a.priority - b.priority || a.id - b.id);
}
```

<Task id="ts-ab02-a5-error">Probiere es aus und lies die Meldungen mit `npm run check`. Welche **neuen** Meldungen kommen in `ticket-list.ts` dazu, und welche ist die **wichtigste**?</Task>

<details>
<summary>Auflösung</summary>

Die erste Meldung ist die wichtige: `Property 'sort' does not exist on type 'readonly Ticket[]'`. Die zwei folgenden (`Parameter 'a' implicitly has an 'any' type` und dasselbe für `b`) sind **Folgefehler**: Weil der Compiler `sort` nicht kennt, weiß er auch nichts über `a` und `b`. Das ist der Grund, warum du immer die **erste** Meldung zuerst liest.

Der Compiler hält das Versprechen der Funktion: `readonly` heißt, dass die Liste nicht verändert wird. Und `sort` würde sie verändern, es ordnet die vorhandene Liste um.

</details>

Wie ernst das gemeint ist, siehst du, wenn du das Versprechen brichst:

<Task id="ts-ab02-a5-break">Ändere den Parameter in `tickets: Ticket[]` (ohne `readonly`). Der Compiler ist zufrieden. Starte `npm run test:ab02`. Welcher Test wird rot, und was steht in der Fehlermeldung?</Task>

<details>
<summary>Auflösung</summary>

Der Test `B5 sortedByPriority › lässt die Eingabeliste unverändert` schlägt fehl, mit `TypeError: Cannot assign to read only property '0' of object '[object Array]'`. Der Test übergibt eine **eingefrorene** Liste: Jeder Versuch, sie zu ändern, löst einen Fehler aus. Genau das ist der Fall, in dem `sort` an der Eingabe scheitert. Hättest du keine eingefrorene Liste gehabt, wäre die Eingabe still durcheinandergeraten.

</details>

<Task id="ts-ab02-a5-fix">Setze `readonly` wieder ein. Sortiere stattdessen eine **Kopie**: `[...tickets]` baut eine neue Liste mit denselben Elementen, und auf der darfst du `sort` aufrufen. Die Tests `B5 sortedByPriority` werden grün.</Task>

:::tip Merke
`sort`, `reverse` und `push` verändern die Liste selbst. `filter`, `map` und `slice` bauen eine neue. Will eine Funktion ihre Eingabe in Ruhe lassen, kopiert sie vor dem Sortieren. Eine Alternative ist `toSorted`, das gleich eine sortierte Kopie liefert.
:::

### Aufgabe 6 – Den Status ändern, ohne die Liste zu verändern

*Etwa 15 Minuten.*

**B6** `withStatus` liefert dieselbe Liste, nur mit anderem Status bei dem Ticket mit der Nummer `id`. Die Eingabe bleibt unverändert, und die anderen Tickets sind dieselben Objekte wie vorher.

<Task id="ts-ab02-a6-java">Schreibe die Funktion zuerst „wie in Java“: Ticket in der Liste suchen, den Status setzen und die Liste zurückgeben.</Task>

```ts
export function withStatus(tickets: readonly Ticket[], id: number, status: Status): Ticket[] {
  for (const ticket of tickets) {
    if (ticket.id === id) {
      ticket.status = status;
    }
  }
  return [...tickets];
}
```

<Task id="ts-ab02-a6-test1">Starte `npm run check`: Der Compiler ist zufrieden. Starte dann `npm run test:ab02`. Welche Tests werden rot?</Task>

<details>
<summary>Auflösung</summary>

Zwei Tests schlagen fehl: `lässt die Eingabeliste und ihre Tickets unverändert` und `liefert eine neue Liste und ein neues Ticket, die anderen Tickets bleiben dieselben Objekte`. Du hast zwar eine neue **Liste** gebaut, aber das **Ticket** darin hast du verändert. Es ist dasselbe Objekt wie in der Eingabe, und die Tests frieren es ein.

Der Compiler hat das nicht bemerkt: `readonly Ticket[]` schützt nur die **Liste**, nicht die Tickets darin.

</details>

Die Lösung: Das geänderte Ticket muss ein **neues Objekt** sein. Mit dem Spread-Operator baust du eine Kopie mit einem überschriebenen Feld:

```ts
{ ...ticket, status }   // neues Ticket, alle Felder wie ticket, nur status ist neu
```

<Task id="ts-ab02-a6-fix">Schreibe `withStatus` mit `map`: Für das Ticket mit der Nummer `id` lieferst du die Kopie mit neuem Status, für alle anderen das Ticket selbst. Die Tests `B6 withStatus` werden grün.</Task>

<summary>Tipp: Bedingung in einer Zeile</summary>

Mit dem Bedingungsoperator `condition ? valueIfTrue : valueIfFalse` kannst du in der Funktion von `map` zwischen den beiden Fällen wählen.

## Zusammenfassung

:::tip Das hast du gelernt
- Eine **Pfeilfunktion** `(x) => x.field` ist eine kurze Funktion, die du an Array-Methoden übergibst.
- **`filter`** behält manche Elemente, **`map`** macht aus jedem etwas anderes, **`find`** liefert das erste passende (oder `undefined`), **`reduce`** macht aus allen einen Wert.
- Das Ergebnis von `find` hat den Typ `Ticket | undefined`. Der Compiler zwingt dich, den Fall „nicht gefunden“ zu behandeln, zum Beispiel mit `?.`.
- **`sort`** (wie `push` und `reverse`) verändert die Liste selbst. Wer eine Liste nicht verändern will, sortiert eine Kopie: `[...tickets].sort(…)`.
- **`readonly Ticket[]`** ist das Versprechen, die Liste nicht zu verändern, und der Compiler überwacht es. Die Tickets in der Liste schützt es nicht.
- Mit **`{ ...ticket, status }`** baust du ein neues Objekt mit einem geänderten Feld. So änderst du Daten, ohne das Original anzufassen.
:::

## Selbstkontrolle

1. Was ist der Unterschied zwischen `filter` und `map`? Wie viele Elemente liefern sie jeweils?
2. Du willst wissen, wie viele Tickets dringend sind. Welche Methoden brauchst du?
3. Warum hat das Ergebnis von `find` den Typ `Ticket | undefined`, und wie gehst du damit um?
4. Was ist bei `reduce` der Zwischenstand (Akkumulator), und wozu dient der Startwert?
5. Warum schreibt man `[...tickets].sort(…)` und nicht `tickets.sort(…)`?
6. Was bewirkt `{ ...ticket, status }`? Warum ist das besser als `ticket.status = status`?

<details>
<summary>Antworten</summary>

1. `filter` behält nur die Elemente, die eine Bedingung erfüllen, und liefert gleich viele oder weniger Elemente, unverändert. `map` macht aus jedem Element etwas anderes und liefert genau so viele Elemente wie die Eingabe.
2. Erst `filter`, um die dringenden Tickets zu behalten, dann `length` für die Anzahl: `tickets.filter(isUrgent).length`.
3. Weil es sein kann, dass kein Ticket die gesuchte Nummer hat. Du behandelst es mit `?.` und gegebenenfalls einem Ersatzwert (`?? …`), oder du prüfst mit `if`, ob das Ergebnis da ist.
4. Der Zwischenstand ist der Wert, den `reduce` von Element zu Element mitträgt, und die Funktion macht daraus jeweils den neuen. Der Startwert ist der Zwischenstand vor dem ersten Element. Bei einer leeren Liste ist er auch das Ergebnis.
5. `sort` verändert die Liste, auf der es aufgerufen wird. Mit der Kopie `[...tickets]` bleibt die Eingabe unverändert, und die Funktion hält ihr `readonly`-Versprechen.
6. Es baut ein **neues** Objekt mit allen Feldern von `ticket`, nur `status` ist anders. Das Original bleibt unverändert. Mit `ticket.status = status` würdest du das Objekt ändern, das auch an anderer Stelle benutzt wird, und könntest Änderungen nicht mehr erkennen.

</details>
