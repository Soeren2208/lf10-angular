# AB 04 – Ein Ticket aufrufen

Die Anwendung bekommt eine zweite Seite: die Ansicht eines einzelnen Tickets, mit einer eigenen Adresse. Dafür lernst du den **Router** und **Services** kennen.

*Dauer: etwas mehr als eine Doppelstunde.*

## Aufgaben

### Aufgabe 1 – Seiten und Adressen

*Etwa 15 Minuten.*

<TaskBadge>T_1 · Seiten und Adressen festlegen</TaskBadge>

Bisher besteht die Anwendung aus einer Seite. Jetzt kommt eine zweite dazu. In einer Angular-Anwendung wechselst du nicht zwischen HTML-Dateien. Der **Router** zeigt je nach Adresse im Browser eine andere Komponente: `/` zeigt das Board, `/tickets/4` das Ticket #4.

<Task id="t2-ab04-a1-generate">Lege mit der Angular-CLI die Komponente `ticket-detail` an, wie in AB 01 die Karte.</Task>

<Task id="t2-ab04-a1-routes">Das Projekt hat schon eine Datei für die Adressen, `app.routes.ts`, aber noch keine Adresse darin. **Tippe** den folgenden Code ab und ersetze dabei den gesamten Inhalt:</Task>

```ts title="src/app/app.routes.ts"
import { Routes } from '@angular/router';
import { TicketBoard } from './ticket-board/ticket-board';
import { TicketDetail } from './ticket-detail/ticket-detail';

export const routes: Routes = [
  { path: '', component: TicketBoard },
  { path: 'tickets/:id', component: TicketDetail },
  { path: '**', redirectTo: '' },
];
```

**So funktioniert das:**

- `routes` ist eine Liste von Adressen. Jeder Eintrag sagt: Bei dieser Adresse zeige diese Komponente.
- `path: ''` ist die Startadresse, bei ihr erscheint das Board.
- `tickets/:id` hat einen Platzhalter: `:id` steht für die Nummer. Die Adresse `/tickets/4` und `/tickets/17` passen beide, die Nummer landet jeweils im Platzhalter.
- `**` passt auf jede andere Adresse. Der Router geht die Liste von oben nach unten durch, deshalb steht dieser Eintrag zuletzt. `redirectTo: ''` schickt unbekannte Adressen zum Board.

<Task id="t2-ab04-a1-app">Die App zeigt jetzt nicht mehr fest das Board, sondern die Komponente, die zur Adresse passt. **Ergänze** in `app.ts` und `app.html` die hervorgehobenen Zeilen, auch die Importe.</Task>

**Das ist neu:**

- `routerLink="/"` macht den Titel zu einem Link zum Board. Die Seite wird dabei nicht neu geladen, nur die Komponente wechselt. Beide Teile, `RouterOutlet` und `RouterLink`, stehen in `imports`, sonst kennt die App sie nicht.

### Aufgabe 2 – Die Angaben eines Tickets

*Etwa 25 Minuten.*

<TaskBadge>T_2 · Die Angaben eines Tickets anzeigen</TaskBadge>

Die Ansicht muss wissen, welches Ticket sie zeigen soll. Das steht in der Adresse, im Platzhalter `:id`. Der Router kann diesen Wert an die Komponente weiterreichen, wie das Board der Karte ein Ticket gibt: als Eingang `input()`. Das musst du einmal in der Konfiguration der Anwendung einschalten.

<Task id="t2-ab04-a2-config">**Ergänze** in `app.config.ts` die hervorgehobenen Zeilen, auch die Importe.</Task>

```ts title="src/app/app.config.ts" {2,6}
import { ApplicationConfig, provideBrowserGlobalErrorListeners } from '@angular/core';
import { provideRouter, withComponentInputBinding } from '@angular/router';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [provideBrowserGlobalErrorListeners(), provideRouter(routes, withComponentInputBinding())],
};
```

`withComponentInputBinding()` sorgt dafür, dass der Router Werte aus der Adresse in gleichnamige Eingänge der Komponente schreibt. Aus dem Platzhalter `:id` wird der Eingang `id`.

<Task id="t2-ab04-a2-class">**Ergänze** in `ticket-detail.ts` die hervorgehobenen Zeilen, auch die Importe.</Task>

```ts title="src/app/ticket-detail/ticket-detail.ts" {1-6,9,14-33}
import { DatePipe } from '@angular/common';
import { Component, computed, input } from '@angular/core';
import { sampleTickets } from '../sample-data';
import { assigneeName, isUrgent } from '../ticket';
import { findTicket } from '../ticket-list';
import { PRIORITY_LABEL, STATUS_LABEL } from '../ticket-labels';

@Component({
  imports: [DatePipe],
  selector: 'app-ticket-detail',
  styleUrl: './ticket-detail.css',
  templateUrl: './ticket-detail.html',
})
export class TicketDetail {
  /** Die Nummer aus der Adresse (`/tickets/:id`). Der Router liefert sie als Text. */
  readonly id = input.required<string>();

  /** Alles, was die Seite zeigt. `undefined`, wenn es das Ticket nicht gibt. */
  protected readonly view = computed(() => {
    const number = Number(this.id());
    const ticket = Number.isInteger(number) ? findTicket(sampleTickets, number) : undefined;
    if (!ticket) {
      return undefined;
    }
    return {
      ticket,
      statusText: STATUS_LABEL[ticket.status],
      priorityText: PRIORITY_LABEL[ticket.priority],
      urgent: isUrgent(ticket),
      assignee: assigneeName(ticket),
    };
  });
}
```

**Das ist neu:**

- `id = input.required<string>()` ist der Eingang für die Nummer aus der Adresse. Eine Adresse besteht aus Text, deshalb ist es ein `string`, auch wenn eine Zahl darin steht.
- `view` ist ein `computed`, denn es hängt vom Signal `id()` ab. Es bereitet alles vor, was die Seite zeigt, und ist `undefined`, wenn es das Ticket nicht gibt.
- `Number(this.id())` macht aus dem Text eine Zahl. Aus `"abc"` wird `NaN`, und `Number.isInteger` ist dafür `false`. Dann ist `ticket` `undefined`, ohne dass etwas abstürzt.
- `findTicket` ist deine Funktion aus der Werkstatt. Sie sucht hier noch direkt in den Beispieldaten.
- `DatePipe` steht in `imports`, weil das Template gleich eine Pipe benutzt.

**Das ist neu:**

- `<dl>` ist die HTML-Liste für Bezeichnung und Wert, `<dt>` die Bezeichnung, `<dd>` der Wert.
- `<h1>` ist die wichtigste Überschrift der Seite. Auf dieser Seite gibt es nur sie, darum steht sie eine Ebene über den Überschriften des Boards.

### Aufgabe 4 – Ein Service für alle Seiten

*Etwa 20 Minuten.*

<TaskBadge>T_4 · Tickets in einem Service für alle Seiten halten</TaskBadge>

Zwei Seiten brauchen dieselben Tickets, also dürfen die Tickets keiner der beiden Seiten gehören. Sie gehören in eine eigene Klasse, die beide benutzen: einen **Service**.

- Ein Service ist eine Klasse mit `@Injectable({ providedIn: 'root' })`. Angular legt von ihr genau **eine** Instanz an, die die ganze Anwendung teilt.
- Eine Komponente holt sich diese Instanz mit `inject(TicketService)`.
- Das kennst du aus Spring: Dort ist es `@Service` und die Instanz kommt über den Konstruktor, das ist **Dependency Injection**. In Angular heißt es `@Injectable` und `inject()`, gemeint ist dasselbe.
- Hält der Service die Tickets in einem Signal, erneuern sich alle Seiten, die es lesen, wenn sich etwas ändert.

<Task id="t2-ab04-a4-service">**Tippe** die Datei `src/app/ticket.service.ts` **ab**. Lege sie dafür im Ordner `src/app` neu an:</Task>

```ts title="src/app/ticket.service.ts"
import { Injectable, signal } from '@angular/core';
import { sampleTickets } from './sample-data';
import type { Status, Ticket } from './ticket';
import { findTicket, withStatus } from './ticket-list';

/** Hält die Tickets für alle Seiten. Wer sie ändert, ändert sie überall. */
@Injectable({ providedIn: 'root' })
export class TicketService {
  readonly tickets = signal<readonly Ticket[]>(sampleTickets);

  /** Das Ticket mit der Nummer `id`, oder `undefined`. Liest das Signal, ist also reaktiv. */
  find(id: number): Ticket | undefined {
    return findTicket(this.tickets(), id);
  }

  setStatus(id: number, status: Status): void {
    this.tickets.update((tickets) => withStatus(tickets, id, status));
  }
}
```

**So ist der Service aufgebaut:**

- Das Signal `tickets` ist jetzt hier zu Hause. `signal<readonly Ticket[]>(…)` legt zusätzlich den Typ fest: eine Liste, die nicht verändert, sondern nur ersetzt wird.
- `find(id)` sucht ein Ticket. Es liest das Signal, deshalb aktualisiert sich ein `computed`, das `find` benutzt, wenn sich die Tickets ändern.
- `setStatus` ist das, was bisher `changeStatus` im Board getan hat.

<Task id="t2-ab04-a4-board">Das Board holt sich die Tickets aus dem Service. **Ergänze** in `ticket-board.ts` die hervorgehobenen Zeilen, auch die Importe.</Task>

```ts title="src/app/ticket-board/ticket-board.ts" {1,4-5,23,29,42}
import { Component, computed, inject, signal } from '@angular/core';
import { isUrgent } from '../ticket';
import type { Status } from '../ticket';
import { sortedByPriority, ticketsWithStatus } from '../ticket-list';
import { TicketService } from '../ticket.service';
import { TicketCard } from '../ticket-card/ticket-card';
import { STATUS_LABEL } from '../ticket-labels';

/** Die drei Spalten des Boards, von links nach rechts. */
const COLUMNS: { status: Status; css: string }[] = [
  { status: 'offen', css: 'open' },
  { status: 'in Arbeit', css: 'progress' },
  { status: 'erledigt', css: 'done' },
];

@Component({
  imports: [TicketCard],
  selector: 'app-ticket-board',
  styleUrl: './ticket-board.css',
  templateUrl: './ticket-board.html',
})
export class TicketBoard {
  private readonly service = inject(TicketService);

  protected readonly urgentOnly = signal(false);

  /** Je Spalte die Tickets, die dringendsten zuerst. Ändert sich ein Signal, rechnet das Board neu. */
  protected readonly columns = computed(() => {
    const tickets = this.urgentOnly() ? this.service.tickets().filter(isUrgent) : this.service.tickets();
    return COLUMNS.map((column) => ({
      css: column.css,
      label: STATUS_LABEL[column.status],
      tickets: sortedByPriority(ticketsWithStatus(tickets, column.status)),
    }));
  });

  protected toggleUrgent(): void {
    this.urgentOnly.update((value) => !value);
  }

  protected changeStatus(id: number, status: Status): void {
    this.service.setStatus(id, status);
  }
}
```

**Das ist neu:**

- `private readonly service = inject(TicketService);` holt die geteilte Instanz. `private` heißt wie in Java: Nur das Board selbst benutzt das Feld, nicht das Template.
- Das Board besitzt keine eigene Liste mehr. Es liest `this.service.tickets()` und ändert sie über `this.service.setStatus(…)`.
- `urgentOnly` bleibt im Board, denn die Auswahl „Nur dringende“ gehört zu dieser Seite und nicht zu den Tickets.

```ts title="src/app/ticket-board/ticket-board.ts" {2,25,47-52}
import { Component, computed, inject, signal } from '@angular/core';
import { Router } from '@angular/router';
import { isUrgent } from '../ticket';
import type { Status } from '../ticket';
import { sortedByPriority, ticketsWithStatus } from '../ticket-list';
import { TicketService } from '../ticket.service';
import { TicketCard } from '../ticket-card/ticket-card';
import { STATUS_LABEL } from '../ticket-labels';

/** Die drei Spalten des Boards, von links nach rechts. */
const COLUMNS: { status: Status; css: string }[] = [
  { status: 'offen', css: 'open' },
  { status: 'in Arbeit', css: 'progress' },
  { status: 'erledigt', css: 'done' },
];

@Component({
  imports: [TicketCard],
  selector: 'app-ticket-board',
  styleUrl: './ticket-board.css',
  templateUrl: './ticket-board.html',
})
export class TicketBoard {
  private readonly service = inject(TicketService);
  private readonly router = inject(Router);

  protected readonly urgentOnly = signal(false);

  /** Je Spalte die Tickets, die dringendsten zuerst. Ändert sich ein Signal, rechnet das Board neu. */
  protected readonly columns = computed(() => {
    const tickets = this.urgentOnly() ? this.service.tickets().filter(isUrgent) : this.service.tickets();
    return COLUMNS.map((column) => ({
      css: column.css,
      label: STATUS_LABEL[column.status],
      tickets: sortedByPriority(ticketsWithStatus(tickets, column.status)),
    }));
  });

  protected toggleUrgent(): void {
    this.urgentOnly.update((value) => !value);
  }

  protected changeStatus(id: number, status: Status): void {
    this.service.setStatus(id, status);
  }

  protected openTicket(input: string): void {
    const number = input.trim();
    if (number !== '') {
      void this.router.navigate(['/tickets', number]);
    }
  }
}
```

**Das ist neu:**

- `inject(Router)` holt den Router, der auch die Adressen verwaltet, genauso wie den Service.
- `openTicket(input)` bekommt den eingegebenen Text. `trim()` entfernt Leerzeichen am Rand. Ist nichts eingegeben, passiert nichts.
- `this.router.navigate(['/tickets', number])` wechselt per Code zur Adresse `/tickets/7`. Das ist das Gegenstück zu `routerLink` im Template. `navigate` braucht etwas Zeit und liefert deshalb ein **Promise**, eine Zusage auf ein Ergebnis, das später da ist. Du wartest hier nicht darauf, und `void` sagt das ausdrücklich.

<div class="toolbar">

    Nur dringende Tickets zeigen

  <div class="open-ticket">

  </div>
</div>

<div class="columns">
  @for (column of columns(); track column.css) {
    <section [class]="'column ' + column.css">
      <h2 class="column-title">
        <span class="dot" aria-hidden="true"></span>
        {{ column.label }}
        <span class="count">{{ column.tickets.length }}</span>
      </h2>

      @for (ticket of column.tickets; track ticket.id) {
        <app-ticket-card [ticket]="ticket" (statusChange)="changeStatus(ticket.id, $event)" />

        <p class="empty">Keine Tickets</p>
      }
    </section>
  }

**Das ist neu:**

- `(keydown.enter)="…"` reagiert nur auf die Eingabetaste. `(click)` auf dem Knopf tut dasselbe, damit man die Nummer mit der Maus oder der Tastatur abschicken kann.

## Das hast du gelernt

- Der **Router** zeigt je nach Adresse eine andere Komponente. Die Adressen stehen in `app.routes.ts`, `<router-outlet />` ist der Platz dafür, `routerLink` verlinkt, `Router.navigate` wechselt per Code.
- Ein Platzhalter wie `:id` in der Adresse landet mit `withComponentInputBinding()` als Eingang in der Komponente, immer als Text.
- Ein **Service** hält Daten, die mehrere Seiten teilen. Angular legt eine Instanz an, jede Komponente holt sie mit `inject(…)`. Mit Signals darin erneuern sich alle Seiten, die sie lesen.
- Mit `@if (…; as v)` und `@else` zeigst du etwas oder sein Gegenteil, und Pipes wie `date` formatieren Werte für die Anzeige.

<summary>Antworten</summary>

1. `<router-outlet />` ist der Platz, an dem der Router die Komponente zur aktuellen Adresse zeigt. `routerLink` macht ein Element zu einem Link auf eine Adresse, ohne dass die Seite neu geladen wird.
2. Board und Ansicht hielten je ihre eigenen Tickets. Der Service hält sie an einer Stelle, und beide lesen von dort. Änderungen sind überall sichtbar.
3. Eine Adresse besteht aus Text. Der Router gibt den Wert, wie er dort steht. Die Umwandlung in eine Zahl machst du selbst mit `Number(…)`.
4. „Ticket nicht gefunden“. `Number('abc')` ist `NaN`, `Number.isInteger` liefert `false`, `ticket` ist `undefined`, `view()` ebenfalls, und der `@else`-Zweig des Templates greift.
