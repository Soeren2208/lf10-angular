## Was ist eine Komponente?

Eine Angular-Anwendung besteht aus **Komponenten**. Eine Komponente ist ein Baustein der Oberfläche, zum Beispiel eine Ticketkarte. Sie besteht aus drei Dateien:

| Datei | Inhalt | Beispiel in diesem Arbeitsblatt |
|---|---|---|
| `ticket-card.ts` | die **Klasse**: Daten und Verhalten | welches Ticket? ist es dringend? |
| `ticket-card.html` | das **Template**: Aussehen als HTML | Nummer, Titel, Marke „dringend“ |
| `ticket-card.css` | der **Stil** | Farben und Abstände |

Das Design-Team hat die Oberfläche im Wireframe in solche Bausteine zerlegt. Mit dem kleinsten fängst du an.

### Aufgabe 4 – Die Komponente anlegen

*Etwa 20 Minuten.*

<TaskBadge>T_4 · Komponente „Ticketkarte“ anlegen</TaskBadge>

<Task id="t2-ab01-a4-generate">Lege die Komponente mit der Angular-CLI an. Gib im zweiten Terminal ein:</Task>

```bash
npx ng generate component ticket-card --skip-tests
```

Die CLI legt einen Ordner `src/app/ticket-card` mit drei Dateien an. Öffne `ticket-card.ts`:

```ts title="src/app/ticket-card/ticket-card.ts"
import { Component } from '@angular/core';

@Component({
  imports: [],
  selector: 'app-ticket-card',
  styleUrl: './ticket-card.css',
  templateUrl: './ticket-card.html',
})
export class TicketCard {}
```

**So ist die Klasse aufgebaut:**

- `@Component({ … })` sagt Angular, was diese Klasse ist. Das kennst du aus Java: Eine Annotation wie `@RestController` tut dasselbe.
- `selector` ist der Name, unter dem du die Komponente in anderen Templates als HTML-Element einsetzt: `<app-ticket-card />`.
- `templateUrl` und `styleUrl` verweisen auf die beiden anderen Dateien.
- `imports` listet die Komponenten, die **dieses** Template benutzt. Das ist wie `import` in Java: Was nicht dasteht, kennt die Komponente nicht.

Jetzt kommt zum ersten Mal HTML dazu. Wenn dir HTML neu ist, klappe die Erklärung auf:

<details>
<summary>HTML in Kürze (aufklappen, wenn dir HTML neu ist)</summary>

HTML beschreibt, **was** auf einer Seite steht, mit **Elementen**. Ein Element sieht so aus: `<name>Inhalt</name>`, mit einem Anfangs-Tag und einem Ende-Tag. Elemente lassen sich ineinander verschachteln, wie Klammern in Java. Die Einrückung zeigt, was in was steckt.

Ein **Attribut** gibt einem Element eine zusätzliche Angabe, zum Beispiel `class="app-title"`. Die Klasse ist ein Name, auf den sich das CSS bezieht. Ein Element kann mehrere Klassen haben, durch Leerzeichen getrennt.

| Element | Wofür |
|---|---|
| `<header>` | der Kopfbereich eines Abschnitts |
| `<main>` | der Hauptinhalt der Seite, es gibt ihn einmal |
| `<article>` | ein in sich abgeschlossener Inhalt, hier eine Ticketkarte |
| `<h1>` bis `<h6>` | Überschriften. `h1` ist die wichtigste, die Zahl gibt die Ebene an. Wie groß die Überschrift aussieht, bestimmt das CSS. |
| `<div>` | ein neutraler Behälter, der Inhalt in einem **Block** zusammenfasst und auf einer eigenen Zeile steht |
| `<span>` | eine neutrale Markierung **innerhalb** einer Zeile |

`header`, `main` und `article` sagen etwas über den Inhalt, `div` und `span` nicht. Browser, Screenreader und Suchmaschinen nutzen das. Die Komponente, die du angelegt hast, setzt du wie ein eigenes HTML-Element ein: `<app-ticket-card />`. Ein Element ohne Inhalt schließt sich selbst mit `/>`.

</details>

<Task id="t2-ab01-a5-class">**Ergänze** in `ticket-card.ts` die hervorgehobenen Zeilen. Importiere, was fehlt: WebStorm schlägt dir den Import mit **Alt + Enter** vor, sobald du den Namen eintippst.</Task>

```ts title="src/app/ticket-card/ticket-card.ts" {1-3,11-17}
import { Component, input } from '@angular/core';
import type { Ticket } from '../ticket';
import { PRIORITY_LABEL } from '../ticket-labels';

@Component({
  imports: [],
  selector: 'app-ticket-card',
  styleUrl: './ticket-card.css',
  templateUrl: './ticket-card.html',
})
export class TicketCard {
  readonly ticket = input.required<Ticket>();

  protected priorityText(): string {
    return PRIORITY_LABEL[this.ticket().priority];
  }
}
```

**Das ist neu:**

- `input.required<Ticket>()` macht aus `ticket` einen **Eingang**: Die Komponente bekommt ihr Ticket von außen, von der Komponente, die sie einsetzt. `required` heißt, dass es nicht fehlen darf.
- Den Wert liest du mit Klammern: `this.ticket()`, nicht `this.ticket`. Warum das so ist, erfährst du in AB 03.
- `protected` heißt wie in Java: Das Template der Komponente darf die Methode benutzen, andere Klassen nicht.

<Task id="t2-ab01-a5-html">**Tippe** den folgenden Code in `ticket-card.html` **ab** und ersetze dabei den gesamten Inhalt. Die Elemente erklärt die Box „HTML in Kürze“ in Aufgabe 4.</Task>

```html title="src/app/ticket-card/ticket-card.html"
<article class="card">
  <header class="card-head">
    <span class="ticket-id">#{{ ticket().id }}</span>
  </header>

  <h3 class="card-title">{{ ticket().title }}</h3>

  <div class="meta">
    <span class="prio" [attr.data-priority]="ticket().priority">{{ priorityText() }}</span>
  </div>
</article>
```

**So funktioniert das Template:**

- Die Karte ist ein `<article>`. Ihr Titel ist eine Überschrift der Ebene 3 (`<h3>`): Die Spalten des Boards bekommen später `<h2>`, die Karten stehen darunter.
- `{{ … }}` setzt einen Wert in den Text ein. Zwischen den Klammern steht ein Ausdruck, hier der Zugriff auf ein Feld des Tickets. Das nennt man **Interpolation**.
- `[attr.data-priority]="…"` setzt ein HTML-Attribut auf den Wert eines Ausdrucks. Die eckigen Klammern bedeuten: Der Wert wird **berechnet**, er ist kein fester Text. Das Attribut steuert die Farbe der Prioritätsmarke im CSS.

<details>
<summary>Lösung: ticket-card.ts</summary>

```ts title="src/app/ticket-card/ticket-card.ts"
import { Component, input } from '@angular/core';
import { isUrgent } from '../ticket';
import type { Ticket } from '../ticket';
import { PRIORITY_LABEL } from '../ticket-labels';

@Component({
  imports: [],
  selector: 'app-ticket-card',
  styleUrl: './ticket-card.css',
  templateUrl: './ticket-card.html',
})
export class TicketCard {
  readonly ticket = input.required<Ticket>();

  protected urgent(): boolean {
    return isUrgent(this.ticket());
  }

  protected priorityText(): string {
    return PRIORITY_LABEL[this.ticket().priority];
  }
}
```

</details>

Jetzt muss das Template die Methode benutzen. Das ist neu.

<Task id="t2-ab01-a6-html">**Ergänze** in `ticket-card.html` die hervorgehobenen Zeilen:</Task>

```html title="src/app/ticket-card/ticket-card.html" {1,4-6}
<article class="card" [class.urgent]="urgent()">
  <header class="card-head">
    <span class="ticket-id">#{{ ticket().id }}</span>
    @if (urgent()) {
      <span class="tag-urgent">dringend</span>
    }
  </header>

  <h3 class="card-title">{{ ticket().title }}</h3>

  <div class="meta">
    <span class="prio" [attr.data-priority]="ticket().priority">{{ priorityText() }}</span>
  </div>
</article>
```

**Das ist neu:**

- `[class.urgent]="urgent()"` schaltet die CSS-Klasse `urgent` an, wenn der Ausdruck wahr ist. Das CSS macht daraus den roten Streifen links.
- `@if (…) { … }` zeigt den Block nur, wenn die Bedingung wahr ist. Das nennt man **Control Flow** (Ablaufsteuerung im Template).

## Das hast du gelernt

- Ein Angular-Projekt legst du mit der **Angular-CLI** an, Komponenten erzeugst du mit `ng generate component`.
- Eine **Komponente** besteht aus Klasse, Template und Stil. Sie hat einen `selector`, unter dem du sie in anderen Templates einsetzt, und `imports` für das, was sie selbst benutzt.
- Mit **`input.required<…>()`** bekommt eine Komponente Daten von außen, mit `[ticket]="…"` gibst du sie ihr mit.
- Im Template setzt `{{ … }}` Werte in den Text ein. `[class.urgent]="…"` und `[attr.data-priority]="…"` binden Klassen und Attribute an Ausdrücke. `@if` zeigt etwas nur unter einer Bedingung.
- Eigener TypeScript-Code aus der Werkstatt lässt sich in Angular unverändert weiterbenutzen.

## Selbstkontrolle

1. Welche drei Dateien gehören zu einer Komponente, und was steht in jeder?
2. Du setzt `<app-ticket-card />` in ein Template, aber der Browser zeigt nichts, und im Terminal steht NG8001. Was fehlt?
3. Was bedeuten die eckigen Klammern in `[ticket]="tickets[3]"`?
4. Warum zeigt Karte #6 trotz Priorität „Hoch“ die Marke „dringend“ nicht?

<details>
<summary>Antworten</summary>

1. Die Klasse (`.ts`) mit Daten und Verhalten, das Template (`.html`) mit dem Aussehen als HTML und der Stil (`.css`) mit Farben und Abständen.
2. Die Komponente steht nicht in der Liste `imports` der Komponente, in deren Template du sie einsetzt.
3. Der Wert wird berechnet. Ohne eckige Klammern wäre `tickets[3]` ein fester Text.
4. Weil `isUrgent` nur offene und in Arbeit befindliche Tickets mit hoher Priorität als dringend einstuft. #6 ist erledigt.

</details>
