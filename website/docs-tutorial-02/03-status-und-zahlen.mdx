# AB 03 – Status und Zahlen

Das Board wird lebendig: Tickets wechseln ihren Stand, und die Spalten zählen mit. Dabei lernst du, warum eine Anzeige veralten kann und wie **Signals** das verhindern.

*Dauer: etwa eine Doppelstunde.*

## Aufgaben

### Aufgabe 1 – Die Karte bietet den Wechsel an

*Etwa 20 Minuten.*

<TaskBadge>T_1 · Karte: Wechsel anbieten und dem Board melden</TaskBadge>

Die Karte zeigt ein Ticket, das ihr das Board gegeben hat. Die Tickets gehören dem Board, deshalb darf die Karte sie nicht selbst ändern. Sie kann dem Board aber **melden**: „Der Benutzer möchte dieses Ticket in den Stand X verschieben.“ Dafür gibt es den **Ausgang** `output()`. Er ist das Gegenstück zum Eingang `input()` aus AB 01: Mit `input()` kommen Daten von oben in die Komponente, mit `output()` gehen Meldungen nach oben hinaus.

<Task id="t2-ab03-a1-class">**Ergänze** in `ticket-card.ts` die hervorgehobenen Zeilen, auch die Importe.</Task>

```ts title="src/app/ticket-card/ticket-card.ts" {1,3,6-14,24,38-40}
import { Component, input, output } from '@angular/core';
import { assigneeName, isUrgent } from '../ticket';
import type { Status, Ticket } from '../ticket';
import { PRIORITY_LABEL } from '../ticket-labels';

/** Wohin ein Ticket von seinem Stand aus wechseln kann, und wie der Knopf heißt. */
const MOVES: Record<Status, { to: Status; label: string }[]> = {
  offen: [{ to: 'in Arbeit', label: 'In Arbeit →' }],
  'in Arbeit': [
    { to: 'offen', label: '← Offen' },
    { to: 'erledigt', label: 'Erledigt →' },
  ],
  erledigt: [{ to: 'in Arbeit', label: '← In Arbeit' }],
};

@Component({
  imports: [],
  selector: 'app-ticket-card',
  styleUrl: './ticket-card.css',
  templateUrl: './ticket-card.html',
})
export class TicketCard {
  readonly ticket = input.required<Ticket>();
  readonly statusChange = output<Status>();

  protected urgent(): boolean {
    return isUrgent(this.ticket());
  }

  protected priorityText(): string {
    return PRIORITY_LABEL[this.ticket().priority];
  }

  protected assignee(): string {
    return assigneeName(this.ticket());
  }

  protected moves(): { to: Status; label: string }[] {
    return MOVES[this.ticket().status];
  }
}
```

**Das ist neu:**

- `output<Status>()` legt den Ausgang `statusChange` an. Der Typ in den spitzen Klammern sagt, was die Karte mitschickt: den neuen Stand. Mit `statusChange.emit(…)` schickt sie die Meldung ab.
- `MOVES` legt fest, wohin ein Ticket von jedem Stand aus wechseln kann. `Record<Status, …>` kennst du. Der Wert ist eine Liste von Wechseln, jeder mit dem neuen Stand (`to`) und dem Text auf dem Knopf (`label`).
- `moves()` gibt die Wechsel für das Ticket der Karte zurück.

**Das ist neu:**

- `(click)="statusChange.emit(move.to)"` ist ein Event-Binding wie `(change)` in AB 02. Beim Klick schickt die Karte den neuen Stand über ihren Ausgang ab.
- `<footer>` ist der Fußbereich der Karte, `<button>` ein Knopf. `type="button"` sagt dem Browser, dass der Knopf nichts abschickt.

```ts title="src/app/ticket-board/ticket-board.ts" {5,23,40-42}
import { Component } from '@angular/core';
import { sampleTickets } from '../sample-data';
import { isUrgent } from '../ticket';
import type { Status } from '../ticket';
import { sortedByPriority, ticketsWithStatus, withStatus } from '../ticket-list';
import { TicketCard } from '../ticket-card/ticket-card';
import { STATUS_LABEL } from '../ticket-labels';

/** Die drei Spalten des Boards, von links nach rechts. */
const COLUMNS: { status: Status; css: string }[] = [
  { status: 'offen', css: 'open' },
  { status: 'in Arbeit', css: 'progress' },
  { status: 'erledigt', css: 'done' },
];

@Component({
  imports: [TicketCard],
  selector: 'app-ticket-board',
  styleUrl: './ticket-board.css',
  templateUrl: './ticket-board.html',
})
export class TicketBoard {
  protected tickets = sampleTickets;
  protected urgentOnly = false;

  /** Je Spalte die Tickets, die dringendsten zuerst. */
  protected columns() {
    const tickets = this.urgentOnly ? this.tickets.filter(isUrgent) : this.tickets;
    return COLUMNS.map((column) => ({
      css: column.css,
      label: STATUS_LABEL[column.status],
      tickets: sortedByPriority(ticketsWithStatus(tickets, column.status)),
    }));
  }

  protected toggleUrgent(): void {
    this.urgentOnly = !this.urgentOnly;
  }

  protected changeStatus(id: number, status: Status): void {
    this.tickets = withStatus(this.tickets, id, status);
  }
}
```

**Das ist neu:**

- `changeStatus(id, status)` ersetzt die Liste `tickets` durch die Liste, die `withStatus` liefert.
- Deshalb steht bei `tickets` kein `readonly` mehr: Das Feld bekommt einen neuen Wert.

### Aufgabe 4 – Der Zustand als Signal

*Etwa 20 Minuten.*

<TaskBadge>T_4 · Zustand des Boards als Signal halten</TaskBadge>

Ein **Signal** ist ein Behälter für einen Wert, in den Angular hineinschauen kann:

- `signal(startwert)` legt ihn an: `signal(sampleTickets)` ist ein Behälter, der die Beispieltickets enthält.
- **Lesen** schreibst du wie einen Funktionsaufruf, mit Klammern: `tickets()`. Dabei merkt sich Angular, wer gelesen hat, zum Beispiel das Template.
- **Schreiben** geht mit `tickets.set(neuerWert)` oder mit `tickets.update((alt) => neu)`. `update` bekommt den alten Wert und liefert den neuen.
- Ändert sich ein Signal, erneuert Angular genau die Stellen, die es gelesen haben. Auch dann, wenn die Änderung von einem Timer kommt.

Jetzt weißt du auch, warum du in AB 01 `ticket()` mit Klammern geschrieben hast: `input()` liefert ein Signal.

<Task id="t2-ab03-a4-class">**Ergänze** in `ticket-board.ts` die hervorgehobenen Zeilen, auch die Importe. Wo eine hervorgehobene Zeile eine alte ersetzt, ersetzt du sie.</Task>

```ts title="src/app/ticket-board/ticket-board.ts" {1,23-24,33,42,46}
import { Component, signal } from '@angular/core';
import { sampleTickets } from '../sample-data';
import { isUrgent } from '../ticket';
import type { Status } from '../ticket';
import { sortedByPriority, ticketsWithStatus, withStatus } from '../ticket-list';
import { TicketCard } from '../ticket-card/ticket-card';
import { STATUS_LABEL } from '../ticket-labels';

/** Die drei Spalten des Boards, von links nach rechts. */
const COLUMNS: { status: Status; css: string }[] = [
  { status: 'offen', css: 'open' },
  { status: 'in Arbeit', css: 'progress' },
  { status: 'erledigt', css: 'done' },
];

@Component({
  imports: [TicketCard],
  selector: 'app-ticket-board',
  styleUrl: './ticket-board.css',
  templateUrl: './ticket-board.html',
})
export class TicketBoard {
  protected readonly tickets = signal(sampleTickets);
  protected readonly urgentOnly = signal(false);

  constructor() {
    // Ein Kollege übernimmt nach fünf Sekunden das Ticket 3.
    setTimeout(() => this.changeStatus(3, 'in Arbeit'), 5000);
  }

  /** Je Spalte die Tickets, die dringendsten zuerst. */

      tickets: sortedByPriority(ticketsWithStatus(tickets, column.status)),

    this.urgentOnly.update((value) => !value);

    this.tickets.update((tickets) => withStatus(tickets, id, status));
  }
}
```

**Das ist neu:**

- `tickets` und `urgentOnly` sind jetzt Signale. Das Feld selbst bekommt nie einen neuen Wert, nur der Behälter ändert seinen Inhalt. Deshalb steht wieder `readonly` da.
- `columns()` liest die Signale mit Klammern: `this.urgentOnly()`, `this.tickets()`.
- `toggleUrgent()` und `changeStatus()` schreiben mit `update`. `(value) => !value` ist eine Pfeilfunktion, die den alten Wert bekommt und den umgekehrten zurückgibt.

### Aufgabe 5 – Abgeleitete Werte mit `computed`

*Etwa 15 Minuten.*

<TaskBadge>T_5 · Abgeleitete Werte mit `computed` berechnen</TaskBadge>

`columns()` ist ein **abgeleiteter** Wert: Er wird aus `tickets` und `urgentOnly` berechnet. Als Methode rechnet er bei jeder Prüfung des Templates von vorn. Für abgeleitete Werte gibt es `computed`:

- `computed(() => …)` berechnet einen Wert aus Signalen. Es merkt sich, welche Signale darin gelesen wurden, und rechnet nur neu, wenn sich eines davon ändert. Sonst liefert es das gemerkte Ergebnis.
- Ein `computed` liest du wie ein Signal, mit Klammern. Im Template ändert sich deshalb nichts: `columns()` bleibt `columns()`.
- Ein `computed` kannst du nur lesen, nicht beschreiben. Sein Wert ergibt sich immer aus den Signalen, von denen er abhängt.

Bei acht Tickets merkst du keinen Unterschied. Bei langen Listen und aufwendigen Berechnungen spart `computed` Arbeit, und der abgeleitete Wert kann nie vom Zustand abweichen, aus dem er entsteht.

<Task id="t2-ab03-a5-class">**Ergänze** in `ticket-board.ts` die hervorgehobenen Zeilen, auch die Importe. Wo eine hervorgehobene Zeile eine alte ersetzt, ersetzt du sie.</Task>

```ts title="src/app/ticket-board/ticket-board.ts" {1,26-27,34}
import { Component, computed, signal } from '@angular/core';
import { sampleTickets } from '../sample-data';
import { isUrgent } from '../ticket';
import type { Status } from '../ticket';
import { sortedByPriority, ticketsWithStatus, withStatus } from '../ticket-list';
import { TicketCard } from '../ticket-card/ticket-card';
import { STATUS_LABEL } from '../ticket-labels';

/** Die drei Spalten des Boards, von links nach rechts. */
const COLUMNS: { status: Status; css: string }[] = [
  { status: 'offen', css: 'open' },
  { status: 'in Arbeit', css: 'progress' },
  { status: 'erledigt', css: 'done' },
];

@Component({
  imports: [TicketCard],
  selector: 'app-ticket-board',
  styleUrl: './ticket-board.css',
  templateUrl: './ticket-board.html',
})
export class TicketBoard {
  protected readonly tickets = signal(sampleTickets);
  protected readonly urgentOnly = signal(false);

  /** Je Spalte die Tickets, die dringendsten zuerst. Ändert sich ein Signal, rechnet das Board neu. */
  protected readonly columns = computed(() => {
    const tickets = this.urgentOnly() ? this.tickets().filter(isUrgent) : this.tickets();
    return COLUMNS.map((column) => ({
      css: column.css,
      label: STATUS_LABEL[column.status],
      tickets: sortedByPriority(ticketsWithStatus(tickets, column.status)),
    }));
  });

  protected toggleUrgent(): void {
    this.urgentOnly.update((value) => !value);
  }

  protected changeStatus(id: number, status: Status): void {
    this.tickets.update((tickets) => withStatus(tickets, id, status));
  }
}
```

`columns` ist jetzt ein Feld mit einem `computed` statt einer Methode. Der Timer aus dem Experiment ist weg.

## Das hast du gelernt

- Mit **`output()`** meldet eine Komponente etwas an die Komponente über ihr, mit `.emit(…)`. Die darüber hört mit `(name)="…"` zu und bekommt den Wert als `$event`.
- Eine Anzeige kann veralten, wenn sich Daten ändern, ohne dass Angular es erfährt, zum Beispiel in einem Timer.
- **Signals** lösen das: `signal(…)` legt sie an, `x()` liest, `x.set(…)` und `x.update(…)` schreiben. Angular erneuert genau die Stellen, die das Signal gelesen haben.
- **`computed`** leitet einen Wert aus Signalen ab und rechnet nur neu, wenn sich eines davon ändert. Es liest sich wie ein Signal.
- `input()` liefert auch ein Signal. Darum schreibst du `ticket()`.

## Selbstkontrolle

1. Was ist der Unterschied zwischen `input()` und `output()`?
2. Im Experiment war die Liste `tickets` nach fünf Sekunden schon geändert, das Board zeigte es aber nicht. Warum?
3. Wie liest du ein Signal, und wie schreibst du es?
4. Wann nimmst du `computed` statt eines `signal`?
5. Warum stimmen die Zahlen über den Spalten immer, auch wenn der Haken gesetzt ist?

<details>
<summary>Antworten</summary>

1. Mit `input()` bekommt eine Komponente Daten von der Komponente über ihr. Mit `output()` meldet sie etwas an diese zurück.
2. Angular zeichnet das Board nur neu, wenn es einen Anlass kennt. Ein Timer ist keiner. Ein Signal sagt Angular Bescheid, sobald es sich ändert.
3. Lesen mit Klammern, `x()`. Schreiben mit `x.set(neuerWert)` oder `x.update((alt) => neu)`.
4. Für Werte, die sich aus anderen Signalen berechnen lassen und nicht selbst geschrieben werden, wie `columns`.
5. Die Zahl ist die Länge der Liste, die die Spalte anzeigt. Diese Liste kommt aus `columns`, und das rechnet sich neu, wenn sich `tickets` oder `urgentOnly` ändert.
